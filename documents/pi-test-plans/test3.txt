ImagePi - Pi 5 test round 3
===========================

What round 2 (Round2Results.txt) showed
PASSED on the Pi:
- install_pi.sh (2 minutes), the venv, the launcher entry, the udev rule, the aarch64 SDK library, "pi_bringup.py check", and the
  test suite (144 passed).
- The app starts from the terminal and from the menu, and quits at once. Theme is remembered.
- Speed: 18 MP pan/zoom is "very smooth" (render test: 35.7 / 31.0 / 23.9 ms median, the target was about 33), CPU about 25% per core
  while panning, memory about 760 MB for the 18 MP RGB image, throttled=0x0 and 49 C throughout.
- cells_gray.png gave 80 particles, the same as the Mac. Time-lapse saved 3 files. Gain and bit depth in the simulated camera work.
- Camera hardware: product id 0547:3018, a 5000M USB 3 link, device node crw-rw-rw-, enumerated as U3CMOS18000KPA.

PROBLEMS found, and what I changed (all on the Mac, none tested on the Pi yet):
1. Real camera: "pi_bringup.py camera" died on the first pull with
     ctypes.ArgumentError: argument 2: TypeError: 'bytearray' object cannot be interpreted as ctypes.c_char_p
   ImagePi gave the SDK wrapper a bytearray and the wrapper only accepts a ctypes buffer. My fake-SDK tests accepted a bytearray, so
   they never caught it; they now reject it like the real wrapper does. The same bug explains round 1's "No live image" in the app:
   the start worked, every pull failed, and the app swallowed the error. Pull errors are now shown in the live view and the status bar.
   (Round 1's E_BUSY was most likely the app still holding the camera while the script ran. Not confirmed, so Part G keeps the checks.)
2. Outlines after Analyze Particles were not visible: they were yellow and 1 px wide on white objects. Now red and 2 px wide.
3. "Add summary row" did nothing visible. The summary now appears as a small "Particle summary" table under the results.
4. Image > Type > 8-bit, then Undo, left the 0..255 display range on the 16-bit data, so it showed as a white page with two black
   dots. Undo and Redo now restore the range when the pixel type changes.
5. Gaussian Blur had no slider: only whole-number settings got one. Settings with a bounded range (sigma, circularity) now have one.
6. Exposure only applied when you pressed Enter. It now applies about 0.3 s after you stop typing or stepping.
7. Auto exposure did nothing in the simulated camera, and the Exposure box never showed what a real camera chooses. The simulator now
   steers to mid-gray, the box is greyed out while auto exposure is on, and it follows the camera's value.
8. The Results table showed 10000 as "1e+04". It now shows 10000, 81369, 1961.25.
9. Speed: Gaussian Blur and the gray display path now use OpenCV (same numbers as SciPy to float precision). On the Mac, 18 MP gray
   Gaussian went from 449 ms to 57 ms, RGB from about 1.4 s to 194 ms, and the fit repaint to about 6 ms. The Pi should gain similarly.
10. The Qt "QWaylandTextInputv3::disableSurface ... but 0x0 is focused" lines are harmless. The app now silences that one message.
Two expectations in test2.txt were wrong, and I corrected that file: the simulated camera cannot reach 20 fps (it needs 42 ms per frame
on the Mac, about 70 ms on the Pi, so 14 fps is a pass), and a 16-bit colour snap is a plain TIFF, not an ImageJ TIFF, so
"imagej_metadata" is None for it by design.

PART C - The real camera in the app
-----------------------------------

Do Part B first. Start the app with: python -m imagepi 2>&1 | tee ~/gui.log

    Start live view. If it fails, the live view now says why under "No live image" (also in the status bar): send me that text.
    If it works, read the fps in the corner and judge smoothness, tearing and lag.

    "Crop W x H (click: full frame)" and the fps should rise. Click it to return to full frame.
C6. Snap at 8-bit. The full-resolution picture opens in a new tab: time it from the click. Save it as TIFF (File > Save As,
    ~/imagepi-test/snap8.tif), then in a terminal:
      python -c "import tifffile,sys; t=tifffile.TiffFile(sys.argv[1]); print('imagej:', t.is_imagej); print((t.imagej_metadata or {}).get('Info')); print(t.pages[0].description[:300])" ~/imagepi-test/snap8.tif

    Expect "imagej: False", then None, then the JSON text (camera, exposure, gain, bits=16). The image must look normal
    (not black, not white). If the camera has no 16-bit mode you get a clear message instead: send it.
C8. Unplug the USB cable WHILE live view runs. Expect a message in the status bar or the panel and the app still running.
    Plug it back in, Camera > Refresh Devices, connect again, Start live view.
C9. Quit the app. Expect the prompt back within a few seconds.
    Send me: the fps at each resolution, the snap time, anything wrong with colours or orientation, what auto exposure did, what
